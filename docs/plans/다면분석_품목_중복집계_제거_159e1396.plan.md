# 다면분석 품목 중복집계 제거 및 세부내역 CSV 추가

## 배경

`app.py`의 `_render_multi_dim_analysis`(약 6665~7044행)에서 품목(`category="소파,식탁"`)을 explode로 행 복제한 뒤 `total_amount`를 그대로 합산하여 매출이 품목 수만큼 중복 계상됨. 주문 1건의 품목별 금액 데이터가 없으므로, 품목 분석은 건수만 제공하고 금액은 주문 단위로만 집계하도록 변경.

## 수정 내용 (모두 `app.py`의 `_render_multi_dim_analysis` 내부)

### 1. 품목 필터를 explode 없이 주문 단위로 적용 (6894~6903행)

- 현재: `품목 in f_dims` 또는 `f_cat` 필터가 있으면 무조건 explode → f_cat만 쓴 경우에도 시군구 등 다른 차원 집계에서 금액 중복 발생.
- 변경: f_cat 필터는 explode 없이 "주문의 품목 목록과 선택 품목의 교집합 존재 여부" 마스크로 주문 행을 필터링. 주문은 1행 유지.
- explode는 "품목이 그룹화 차원에 포함된 경우"에만, 피벗 직전에 별도 DataFrame(`fdf_expl`)으로 수행.

### 2. 요약 4카드는 항상 주문 단위로 계산 (6909~6917행)

- 건수·매출액·객단가·고객수를 explode 이전의 주문 단위 `fdf`에서 계산 → 품목 차원을 선택해도 상단 요약은 절대 부풀려지지 않음.

### 3. 품목 차원 선택 시 측정값 자동 '건수' 전환 (6933행 인근)

- `"품목" in q["f_dims"]`이고 측정값이 매출액(원)/객단가(원)이면 유효 측정값을 `건수`로 강제 전환.
- `st.info`로 안내: "품목은 주문 단위 금액만 존재하여 품목별 금액 분석이 불가능합니다. 건수 기준으로 자동 전환되었습니다."
- 피벗·차트(막대/히트맵/트리맵)·표 포맷은 전환된 측정값(건수)을 사용.

### 4. 세부 매출 내역 CSV 추가 (6965~6984행 CSV 섹션)

- 기존 "피벗 결과 CSV" 옆에 "세부 내역 CSV" 버튼 추가 (동일한 2단계 준비→다운로드 패턴, 별도 session_state 키).
- 내용: 필터 적용된 주문 단위 행(중복 없음) — 주문일, 매장(있으면), 시도, 시군구, 법정동, 건물명, 고객명(name), 주소, 품목(원본 콤마 문자열), 매출액(total_amount), 방문이유, 구매이유.
- 세부 내역의 매출액 합계 = 요약 카드 매출액과 정확히 일치 → 중복 검증 가능.

## 검증

- 품목 차원 선택 + 매출액 선택 → 건수로 자동 전환 및 안내 표시 확인.
- 복수 품목 주문 1건이 요약 카드에서 1건/실제 금액으로만 집계되는지 확인.
- 세부 내역 CSV 합계가 요약 카드 매출액과 일치하는지 확인.
- 완료 후 커밋·푸시.
