# 입력 폼 팝업(모달) 전환 플랜

## 배경

현재 여러 입력·편집 UI 가 **인라인(같은 페이지 안에 노출)** 방식이라 다음 문제가 있음:

1. **리드고객 관리** — 리드 목록에서 `관리` 버튼을 누르면 상세 패널이 화면 최상단으로 이동하여 렌더링됨. 편집 뒤 목록으로 돌아오려면 다시 스크롤 필요.
2. **내 근태 · 내 신청 내역** — 개별 신청 수정(`✏️`) 시 같은 위치에 편집 컨테이너가 펼쳐지지만, 신청 수가 많거나 목록 하단에 있는 항목이면 저장 후 원래 위치를 다시 찾아야 함.
3. **문서/매장/근무일정 등** — 편집 대상이 목록 위 또는 아래로 밀려나 사용자 인지 부담이 큼.

사용자가 첨부한 이미지처럼 **클릭하면 화면 중앙에 카드형 팝업 → 편집 → 저장 → 자동 닫힘** 흐름으로 통일하면 스크롤 왕복이 사라지고, 편집 시점의 화면 컨텍스트(목록 위치, 필터 상태)가 유지되어 UX 가 개선됨.

## 목표 (성공 기준)

- [ ] 아래 대상 화면들이 `st.dialog` 기반 팝업으로 열림 (인라인 컨테이너 제거)
- [ ] 팝업 안에서 `저장/등록` 버튼 클릭 시 DB 반영 후 자동으로 닫히고 목록이 새로고침됨
- [ ] `취소/닫기` 버튼은 팝업만 닫고 스크롤 위치·필터·검색어를 유지
- [ ] `st.dialog` 미지원 환경(Streamlit < 1.33)에서는 기존 인라인 방식으로 자동 폴백
- [ ] 팝업 밖 배경 클릭·ESC 로 닫아도 데이터 손실 없음 (저장 안 눌렀으면 변경사항은 버려짐이 명시적으로 알려짐)

## 기술 스택

- **Streamlit `st.dialog`** (v1.33+, `requirements.txt` 는 `>=1.28.0` 이므로 폴백 필수)
- `st.session_state` 기반 열림 상태 관리 (기존 `lead_selected_id`, `my_adj_editing_id`, `doc_editing_*` 등을 그대로 재사용)
- 기존 `_address_search_dialog` (`app.py` L5726) 구현 패턴 재사용

### 공통 헬퍼 도입 (`_open_dialog`)

`app.py` 상단부(공용 유틸 근처)에 다음 헬퍼를 배치. 각 화면은 `render_fn` 만 넘겨 재사용.

```python
def _open_dialog(title: str, render_fn, *, width: str = "large",
                 fallback_expander: bool = True) -> None:
    """st.dialog 로 팝업을 연다. 지원 안 되면 expander 로 폴백.

    render_fn: () -> None  (팝업 안 UI 그리는 함수. 저장 성공 시 st.rerun() 호출)
    width: 'small'|'medium'|'large' (st.dialog 인자)
    """
    if hasattr(st, "dialog"):
        try:
            try:
                dec = st.dialog(title, width=width)
            except TypeError:
                dec = st.dialog(title)

            @dec
            def _dlg():
                render_fn()

            _dlg()
            return
        except Exception:
            pass
    if fallback_expander:
        with st.expander(f"📌 {title}", expanded=True):
            render_fn()
    else:
        render_fn()
```

### 열림 상태 트리거 패턴

기존 방식과 동일. `관리` 버튼 클릭 → `st.session_state["lead_selected_id"] = _lid` 저장 → `st.rerun()` → 다음 렌더에서 세션 값이 있으면 `_open_dialog(...)` 호출.

```python
if _sel_id := st.session_state.get("lead_selected_id"):
    _sel = next((l for l in leads_raw if l.get("id") == _sel_id), None)
    if _sel:
        _open_dialog(
            f"📋 {_sel.get('name') or '리드'} 상세 관리",
            lambda: _render_lead_detail_panel(_sel, emp_map),
            width="large",
        )
```

닫기 처리: 팝업 내부 `취소` 버튼 → `st.session_state.pop("lead_selected_id", None); st.rerun()`.

### 1. 리드고객 상세 관리 (`lead_management.py`)

**현재 (문제 지점)**

**변경 (팝업)**

```python
_sel_id = st.session_state.get("lead_selected_id")
if _sel_id:
    _sel = next((l for l in leads_raw if l.get("id") == _sel_id), None)
    if _sel:
        def _render():
            _render_lead_detail_panel(_sel, emp_map)
            st.divider()
            if st.button("닫기", key=f"lead_dlg_close_{_sel_id}", width="stretch"):
                st.session_state.pop("lead_selected_id", None)
                st.rerun()
        _open_dialog(
            f"📋 {_sel.get('name') or '리드'} 상세 관리",
```

## 리스크 및 대응

1. **`st.dialog` 은 렌더 시점에 함수를 실행하므로, 팝업 안에서 `st.rerun()` 하면 팝업이 자동 닫힘.** → 저장 로직 마지막에 반드시 `st.rerun()` 호출 필요. 이미 대부분 그렇게 되어 있음.
2. **팝업 안 form 안에서 `on_change` 콜백**은 dialog 재실행을 유발할 수 있음 → 리드 목록의 인라인 `on_change=_inline_save_*` 는 팝업이 아니라 **목록 행**에 유지 (현재 그대로).
3. **폭 문제** — `st.dialog(width="large")` 는 약 700px. 상담 히스토리 등이 잘리면 팝업 안 자체 스크롤 (Streamlit 이 기본 지원).
4. **모듈 간 의존** — `lead_management.py` 가 `app.py` 의 헬퍼를 import 하는 것이 무리라면, 헬퍼를 별도 `ui_helpers.py` 로 분리해 양쪽에서 import.
