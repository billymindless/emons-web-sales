# 잔금 단건 결제 → 복수결제 지원

## 대상

공통 함수 [`_customer_balance_payment_ui`](app.py) (약 26742–26915행).

호출처는 모두 동일 폼을 쓰므로 **한 곳만 바꾸면** 아래가 함께 복수결제가 됩니다.

- 고객 및 잔금관리 → 잔금 추가 결제 → **개별 주문 단건 결제** (약 29355행)
- 미수금 레포트 「잔금 결제 처리」
- 신규판매 「기존 주문 잔금 빠른 등록」

참고 구현: [`render_new_sales`](app.py) 복수 결제 블록 (약 25929–26050 렌더, 26052+ 검증·저장).

```mermaid
flowchart LR
  UI["결제 슬롯 N개"] --> Valid["금액>0 슬롯 검증"]
  Valid --> Loop["슬롯별 app_payments INSERT"]
  Loop --> Recalc["잔금/마진 1회 재계산"]
  Recalc --> Hist["PaymentHistory 합산 기록"]
```

## UI 변경 (`_customer_balance_payment_ui`)

기존: 결제수단 1 · 금액 1 · 카드사/승인번호 1.

변경:

1. **결제 날짜**·**결제 메모**는 공통 1개 유지 (한 번의 「결제 등록」에 동일 결제일 적용).
2. 헤더: `결제 내역 (복수 결제 가능)` + `➕ 결제 수단 추가` (최대 20).
3. 슬롯 상태 키는 `key_prefix`로 격리해 주문별 expander 충돌 방지:
   - `{key_prefix}_slot_count` (기본 **1**)
   - `{key_prefix}_method_{i}`, `{key_prefix}_card_{i}`, `{key_prefix}_amt_{i}`
   - 온누리: `{key_prefix}_onnuri_stage_{i}` / `_last4_{i}` / `_full_{i}` / `_receipt_{i}`
4. 각 슬롯 3열: 결제 수단 · 카드사(또는 승인번호) · 금액 — 매출 등록과 동일 분기 (`_CARD_WITH_COMPANY` / 메인페이 / 지역화폐 / 온누리).
5. **1번 슬롯 금액 기본값** = 현재 잔금(콤마 포맷). 추가 슬롯 기본값 `0`.
6. 실시간 표시: `이번 결제 합계` / `등록 후 예상 잔금` (= `balance - sum`). 합계가 잔금 초과 시 기존과 같이 **경고만** (차단 없음).

## 검증·저장

「결제 등록」 클릭 시:

1. `amt > 0` 슬롯만 대상으로 수집. 합계 0이면 `"금액을 입력하세요."`.
2. 슬롯별 필수값 (매출 등록과 동일 수준):
   - 신용/체크 → 카드사
   - 메인페이 → 승인번호 4자리
   - 지역화폐 → 승인번호
   - 온누리(전자) → 뒤 4자리 → 중복 시 전체 8자리+ (`_count_payments_onnuri_dup_supabase` / SQLite 동일 로직)
3. `amt > 0` 슬롯마다 `_payment_fee_amount` 계산 후:
   - Supabase: `_insert_payment_supabase` 반복
   - SQLite: `INSERT INTO Payments` 반복
4. INSERT 루프 종료 후 **1회** `_recalc_order_actual_margin_supabase` (또는 SQLite `_recalc_order_actual_margin`).
5. `PaymentHistory` / audit: `added_amount` = 합계, `payments` 배열에 슬롯별 `{method, card_company, amount}` 기록. 성공 토스트·`_pay_done_*`도 합계 금액으로 표시.
6. 성공 후 해당 `key_prefix`의 슬롯 위젯 키·`slot_count` 정리 후 `st.rerun()`.

기존 정책 유지: 부분 결제·초과 결제 허용, 결제일은 폼의 date_input 값.

## 범위 밖

- `_multi_order_split_payment_ui`(복수 **주문** × 수단 1개)는 변경하지 않음.
- DB 스키마 변경 없음 (`app_payments` 행만 여러 건 INSERT).

## 검증

- 주문 1건: 신용카드 50만 + 현금 나머지 → `app_payments` 2행, 잔금 0.
- 온누리 슬롯 포함 시 승인번호/중복 단계 동작.
- 금액 전부 0 → 등록 차단.
- 초과 합계 → 경고 후 등록 가능, 잔금 음수/`이상결제` 처리가 기존 recalc와 일치하는지 확인.
