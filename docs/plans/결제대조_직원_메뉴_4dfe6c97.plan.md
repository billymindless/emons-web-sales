# 결제 대조를 직원 메뉴로 이동

## 권한
- `user` (일반 직원): 자기 매장 결과표 조회, 행 선택 승인번호 팝업, 금액 동일 쌍 빠른 수정, 엑셀 다운로드.
- `store_admin`: 같은 메뉴에서 위 기능에 더해 원장 업로드·검증 시작일 저장·재매칭·수동/AI 매칭·중복 행 강제 등록.
- `superadmin`: 세일즈 메뉴가 없으므로 기존 `⚙️ 관리자 설정` 8번을 그대로 두고, 전 매장 업로드까지 유지.

직원에게 숨기는 것: 업로드 이력, 파일 업로더, `업로드 & 자동 매칭`, 사업자 선택, 중복 충돌 패널, 시작일 저장 버튼, `재검증/재매칭`, AI 유사 매칭, 수동 맞추기, ERP-only 수기 확인.

## 메뉴 추가 — [app.py](app.py) `_get_sales_tab_labels` (약 330행)

기존 인덱스와 1:1인 화면이 밀리지 않게 **목록 맨 끝**에만 추가한다.

- 일반 직원: `"11. 💳 결제 대조"` (현재 마지막이 FAQ, 인덱스 10)
- 매장 관리자: `"15. 💳 결제 대조"` (현재 마지막이 상권 맵, 인덱스 14)

## 화면 연결 — [app.py](app.py) `main()` 디스패치 (약 45532행)

- `role == "user" and idx == 10` → `_render_external_pay_admin_section(role, username, allow_upload=False)`
- `role == "store_admin" and idx == 14` → 같은 함수, `allow_upload=True`

## 업로드 차단 — `_render_external_pay_admin_section` (약 33648행)

시그니처에 `allow_upload: bool = True` 를 추가한다. `False` 일 때:

- 업로드 이력 표, `st.file_uploader`, 업로드 버튼, 사업자 선택, `_render_ext_pay_conflict_panel` 를 그리지 않는다.
- 검증 시작일 입력은 조회용으로 남기고, `시작일 저장` 버튼만 숨긴다.
- `재검증/재매칭` 버튼을 숨긴다.
- 결과표 아래에서는 `_render_ext_pay_quick_approval_fix` 와 승인번호 팝업·선택 목록만 남긴다.
- `_render_ext_pay_ai_similar_match`, `_render_ext_pay_manual_match_ui`, `_render_ext_pay_reconcile_section`, `_render_ext_pay_manual_and_erp_only` 는 `allow_upload` 일 때만 호출한다.

매장 범위는 이미 비-superadmin 이면 `current_db` 한 곳만 고를 수 있다. 직원은 다른 매장 원장을 보지 못한다.

## 관리자 설정 — `render_admin_settings` (약 35659행)

- `store_admin`: 8번 업로더 블록을 빼고, "좌측 메뉴 15. 결제 대조에서 엽니다" 안내만 남긴다.
- `superadmin`: 기존처럼 `_render_external_pay_admin_section(..., allow_upload=True)` 를 8번에 유지한다.

승인번호 저장 경로는 그대로다. `_update_payment_supabase` 가 승인번호만 바꾸고 재매칭한다. 원장 테이블 `app_external_pay_rows` 는 직원이 호출하지 않는다.
