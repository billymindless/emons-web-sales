# 임포트 완납 처리 · 기존 잔금 비덮어쓰기

## 문제

현재 [`legacy_purchase_import_service.py`](legacy_purchase_import_service.py) 의 `to_create` 는 `balance_status='완납'` 만 넣고 **`app_payments` 를 만들지 않음**.

미수 탭([`app.py`](app.py) `tab_d10` / `tab_overdue`)은 아래처럼 **결제 합 기준**으로 잔금을 계산함:

```python
orders["balance"] = orders["total_amount"] - orders["paid"]
mask_balance = orders["balance"] > 0
```

→ 임포트 주문이 미수 목록·레포트에 전액 미수로 잡힘.

반면 `to_attach` 는 이미 주문 헤더를 UPDATE 하지 않고 라인만 INSERT. 이 경로는 **잔금/금액 비덮어쓰기**를 코드로 명시·검증만 강화하면 됨.

```mermaid
flowchart TD
    Group[엑셀 주문 그룹] --> Match{(customer_id, order_date) 후보}
    Match -->|0건 to_create| Create["app_orders INSERT 완납 + app_payments 전액 INSERT"]
    Create --> Items1[app_order_items INSERT]
    Match -->|1건 to_attach| Attach["주문/결제/잔금 절대 UPDATE 안 함"]
    Attach --> Items2[app_order_items INSERT만]
    Match -->|2건+ unresolved| Manual[수동 선택 후 동일 규칙]
```

## 규칙 (확정)

| 케이스 | 동작 |
|---|---|
| 모모에 동일 (고객, 등록일) 주문 **없음** (`to_create`) | 판매가 역산으로 주문 생성 + `balance_status=완납` + **판매가 전액 결제 1건 INSERT** → 미수 처리 안 함 |
| 모모에 주문 **있음** (`to_attach`, 잔금>0 포함) | `total_amount` / `cost_price` / `balance_status` / `app_payments` **일절 변경 안 함**. 라인 아이템만 추가 |
| 수동 매칭으로 기존 주문 선택 | attach 와 동일 (비덮어쓰기) |
| 수동 매칭으로 신규 등록 | to_create 와 동일 (완납 결제 생성) |

결제 수단 표기: `payment_method='과거완납(임포트)'`, `payment_date=order_date`(없으면 delivery_date), `amount=sale_price`, `fee_amount=0`, `created_by` 는 임포트 실행자.

## 구현

### 1. [`legacy_purchase_import_service.py`](legacy_purchase_import_service.py) — commit

- `_payment_payload_from_group(g, order_id, db_filename, created_by)` 헬퍼 추가.
- `commit_import` Phase 2 직후 (신규 주문 id 확보 후) **Phase 2b: to_create 주문에 대해서만** `app_payments` 배치 INSERT.
- Phase 3 `to_attach` 경로에 주석 + 가드: 주문 UPDATE / 결제 INSERT 호출이 없음을 유지. `PurchaseCommitResult` 에 `payments_inserted` 카운트 추가.
- `_fetch_existing_orders` meta 에 `balance_status` 포함 → 미리보기 사유에 `기존잔금유지` 표시 가능하도록.

### 2. 미리보기 UI ([`app.py`](app.py) `_render_legacy_purchase_bulk_import`)

- `preview_to_dataframe` 상태 문구:
  - 신규 주문 → `신규(완납)`
  - 자동 매칭 → `라인만 추가(기존 금액·잔금 유지)`
- caption 한 줄 추가: 신규는 미수 제외, 기존 주문은 잔금/금액을 덮어쓰지 않음.

### 3. 미수 탭 방어 ([`app.py`](app.py) tab_d10 / tab_overdue)

이미 임포트된 건(결제 없는 완납)도 즉시 제외되도록, 공유 주문 로드 컬럼에 `balance_status` 추가 후:

```python
mask_balance = (orders["balance"] > 0) & (~orders["balance_status"].isin(["완납", "이상결제"]))
```

(AI 리포트·대시보드와 동일 기준. 기존 잘못된 임포트도 재임포트 없이 미수에서 빠짐.)

### 4. 롤백 연동 ([`legacy_purchase_import_service.py`](legacy_purchase_import_service.py) `commit_rollback`)

임포트 주문 삭제 전에 해당 `order_id` 의 `app_payments` 를 먼저 배치 DELETE (주문 FK/고아 결제 방지). preview 에 `payments_to_delete` 건수 표시.

## 검증

- Dry-run: to_create 1건 → orders+payments+items 생성, `paid==total_amount`, 미수 탭 미포함.
- to_attach: 기존 `balance_status=미납`, `total_amount` 불변, payments 건수 불변, items 만 증가.
- 롤백 연도 삭제 시 해당 주문의 임포트 결제도 함께 삭제.

## 범위 밖

- 엑셀에 실제 “잔금” 컬럼이 있어도 신규 주문에는 반영하지 않음(항상 완납).
- attach 시 기존 잔금이 있어도 라인 attach 자체는 허용(금액만 비덮어쓰기).
