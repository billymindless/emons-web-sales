# 다면 분석 UX 및 성능 개편

## 배경 (현재 문제)

- 대상: `_render_multi_dim_analysis()` ([app.py:6486](app.py))
  - 호출부: `render_marketing_insights_tenant()` ([app.py:6935](app.py)), `render_marketing_insights_superadmin()` ([app.py:7052](app.py))
- 위젯 변경 시마다 함수 전체가 재실행되며 (필터 → merge → groupby → Plotly 3종 렌더링) 그 사이 DOM 이 잠깐 비워지는 것이 "화면 하얘짐" 의 원인
- 시군구 옵션이 전 데이터의 unique 값(예: 남구·해운대구·서구 혼재) 을 그대로 노출 — 상위 시도 계층이 없음
- `app_customers` 스키마: `sigungu` = Kakao `region_2depth_name` ("남구" 형식), `sido` 컬럼 없음 → 정적 매핑 테이블로 계층 구성 예정

## 변경 개요


## 구현 상세

### 1. 정적 시도↔시군구 매핑

`app.py` 의 `_classify_building_type()` 근처에 두 개의 상수를 추가:

```python
_KR_SIDO_SIGUNGU_MAP: dict[str, list[str]] = {
    "서울특별시": ["강남구", "강동구", ... ],
    "부산광역시": ["강서구", "금정구", "기장군", ... ],
    "울산광역시": ["남구", "동구", "북구", "중구", "울주군"],
    "경상남도": ["창원시", "양산시", "김해시", ...],
    # ... 17개 시도 전체
}
_KR_SIGUNGU_TO_SIDO: dict[str, str] = {
    sigungu: sido
    for sido, sigungu_list in _KR_SIDO_SIGUNGU_MAP.items()
    for sigungu in sigungu_list
}
```

- DB 변경 없음. 신규 지역 추가 시 이 dict 만 업데이트.
- 매핑에 없는 sigungu 는 "(기타)" 시도로 분류하여 노출 (부산 등 광역시 시군구가 중복되는 경우도 있으므로 실제로는 매장별로 접두어 힌트를 사용할 여지가 있음 — 매장 소재 시도를 우선 매칭에 활용).

### 2. 다면 분석을 자체 `@st.fragment` 로 분리

현재 `render_marketing_insights_tenant/_superadmin` 이 `@st.fragment` 지만 그 안에 다중 기간 비교 차트 (`_render_marketing_multi_period_comparison`) 와 다면 분석이 함께 있어, 다면 분석의 검색 버튼 클릭이 위 다중 기간 차트도 재렌더링시킴.

- `_render_multi_dim_analysis()` 위에 `@st.fragment` 데코레이터 부착.
- 반환 후 상위 프래그먼트로 되돌아가지 않도록 `st.rerun(scope="fragment")` 를 검색 버튼 처리 시 사용.

### 3. `st.form` 기반 필터 UI

`_render_multi_dim_analysis` 내부의 필터 위젯 전체(6543-6640 라인) 를 다음 구조로 재구성:

```python
with st.form(f"{key_prefix}_mdim_form", clear_on_submit=False):
    # 기간 · 매장(superadmin)
    # 지역 계층: 시도 → 시군구 → 법정동 → 도로명
    # 건물명 · 건물유형
    # 품목 · 방문이유 · 구매이유
    # 그룹화 차원 · 측정값
    submitted = st.form_submit_button("🔍 검색", type="primary")

if submitted:
    st.session_state[f"{key_prefix}_mdim_query"] = {
        "f_start": f_start, "f_end": f_end,
        "f_sido": f_sido, "f_sigungu": f_sigungu,
        "f_bname": f_bname, "f_road": f_road,
        # … 나머지 필터 값
        "f_dims": f_dims, "metric": metric,
    }

q = st.session_state.get(f"{key_prefix}_mdim_query")
if not q:
    st.info("검색 조건을 설정한 뒤 위의 [🔍 검색] 버튼을 눌러주세요.")
    return

with st.spinner("검색 중…"):
    # 필터 적용 → groupby → 요약·표·차트 렌더링
    ...
```

- Streamlit 기본 `st.spinner` 는 상단에 작은 원형 아이콘 + 텍스트로 렌더되어 사용자가 요청한 "크지 않은 모래시계" 요구와 부합.
- 폼 안에서 `st.multiselect` 를 변경해도 폼 미제출 상태이므로 재실행이 일어나지 않아 화면 깜빡임 없음.

### 4. 지역 계층 필터 (시도 → 시군구 → 법정동 → 도로명)

폼 내부 지역 필터 4단 구성 (현재 3단):

```python
# df["sido"] 를 매핑으로 파생 (렌더 시 1회만)
df["sido"] = df["sigungu"].map(_KR_SIGUNGU_TO_SIDO).fillna("(기타)")

rc1, rc2 = st.columns(2)
with rc1:
    sido_opts = sorted(df["sido"].dropna().unique())
    f_sido = st.multiselect("시도", sido_opts, placeholder="전체", key=f"{key_prefix}_mdim_sido")
with rc2:
    _sg_pool = df if not f_sido else df[df["sido"].isin(f_sido)]
    sigungu_opts = sorted(_sg_pool["sigungu"].dropna().unique())
    f_sigungu = st.multiselect("시군구", sigungu_opts, placeholder="전체", key=f"{key_prefix}_mdim_sigungu")

rc3, rc4 = st.columns(2)
with rc3:
    _bn_pool = _sg_pool if not f_sigungu else _sg_pool[_sg_pool["sigungu"].isin(f_sigungu)]
    bname_opts = sorted(_bn_pool["bname"].dropna().unique())
    f_bname = st.multiselect("법정동", bname_opts, placeholder="전체", key=f"{key_prefix}_mdim_bname")
with rc4:
    _rn_pool = _bn_pool if not f_bname else _bn_pool[_bn_pool["bname"].isin(f_bname)]
    rn_opts = sorted(_rn_pool["road_name"].dropna().unique())
    f_road = st.multiselect("도로명", rn_opts, placeholder="전체", key=f"{key_prefix}_mdim_road")
```

- 시도 미선택 = 전 시도 대상. 시도 선택 시 시군구 옵션 자동 축소.
- 도로명·법정동은 상위 선택 범위 안에서만 노출됨 (사용자 요구: "입력된 곳 중심").
- `dim_map` 에도 `"시도": "sido"` 추가하여 그룹화 차원으로도 사용 가능.

### 5. 성능 개선

`_render_multi_dim_analysis` 진입 시점 정리(위젯 재실행 감소):

- **폼 지연 실행** (§3): 위젯 변경마다 오는 재실행을 완전히 제거. 가장 큰 체감 개선.
- **프래그먼트 분리** (§2): 상단 다중 기간 비교 차트 재렌더 방지.
- **CSV 지연 인코딩**: 현재 `display_df.to_csv(...).encode(...)` 가 재실행마다 실행됨 → 2단계 버튼으로 변경.
  ```python
  if st.button("📥 CSV 준비"):
      st.session_state[f"{key_prefix}_mdim_csv_bytes"] = display_df.to_csv(index=False).encode("utf-8-sig")
  _csv = st.session_state.get(f"{key_prefix}_mdim_csv_bytes")
  if _csv:
      st.download_button("💾 다운로드", _csv, file_name=..., mime="text/csv")
  ```
- **지역 병합 캐시**: `_load_customers_region_cached()` 는 이미 `ttl=300` 캐시가 걸려 있음. `df.merge(reg_all, ...)` 자체는 매번 실행되지만 상대적으로 저비용.
- **옵션 리스트 재계산 최소화**: 폼 안 옵션 계산은 이제 폼 초기 렌더링에서 1회만 실행 (제출 전 재실행 없음).
- **차트 렌더링 임계값**: 결과 행이 500 초과이면 차트 자동 생략 + "차트 보기" 체크박스 노출. Plotly 는 큰 데이터셋일수록 브라우저 렌더가 오래 걸림.

## 검증 항목

- 첫 진입 시: 필터 위젯만 보이고 결과 영역엔 "검색 버튼을 눌러주세요" 안내
- 폼 안에서 시도·시군구·기타 위젯 변경 시 화면 재렌더링 없음
- [검색] 클릭 시: 소형 스피너 노출 → 요약·표·차트 렌더링
- 시도 선택 시 시군구 옵션이 해당 시도로 축소되는지
- 시군구 선택 없이도 검색 가능한지
- CSV 다운로드가 새 데이터로 갱신되는지
- 다중 기간 비교 차트가 다면 분석의 재실행에 영향을 받지 않는지 (프래그먼트 격리 검증)
